# راهنمای استفاده‌ی EZ Scanner

این راهنما مرحله‌به‌مرحله و به فارسی است: از نصب تا گرفتن یک کانفیگ تمیز.

---

## ۰. پیش‌نیاز

- **Node.js 22.18 یا بالاتر** (نسخه‌ی ۲۴ توصیه می‌شود). در ویندوز از [nodejs.org](https://nodejs.org) نصب کنید (نسخه‌ی LTS).
- اطمینان از نصب: `node -v`
- نیازی به Go، WebView2، پایتون یا هیچ ابزار دیگری نیست.

---

## ۱. اجرای رابط گرافیکی

```bash
git clone https://github.com/ezzaeskardi-afk/EZ_scanner.git
cd EZ_scanner
npm install
npm start
```

مرورگر خودش باز می‌شود. اگر باز نشد، آدرسی که در ترمینال چاپ می‌شود (مثل
`http://127.0.0.1:8788/?token=…`) را دستی باز کنید.

> ویندوزی‌ها می‌توانند `start-gui.cmd` را دوبار کلیک کنند.

---

## ۲. کار سریع (سه کلیک)

1. در تب **کانفیگ**، لینک کانفیگ خودتان (`vless://…` یا `trojan://…`) را پیست کنید.
2. دکمه‌ی **تحلیل کانفیگ** و بعد **استفاده از SNI/پورت آن**.
3. دکمه‌ی **شروع اسکن**.

بعد از پایان، جدول نتیجه‌ها پر می‌شود. ستون «وضعیت» را ببینید:
- `✓` = سالم و آماده‌ی استفاده
- متن قرمز = دلیل رد شدن (مثلاً `loss 67% > 50%`)

---

## ۳. تنظیمات مهم (و اینکه چه چیزی را روشن نکنید)

| تنظیم | پیشنهاد | توضیح |
|---|---|---|
| حالت (Mode) | `tls` | `tcp` سریع‌تر ولی سطحی؛ `http` دقیق‌تر ولی کندتر |
| تعداد تلاش / حداقل موفقیت | `3` / `2` | برای خط‌های بد: `2` / `1` |
| ورکر | `20` تا `50` | بیشتر از ۱۵۰ روی خطوط ایران ریسک قطعی دارد |
| **بررسی WebSocket** | ❌ خاموش | اگر روشن باشد روی خطوط دارای DPI همه چیز قرمز می‌شود |
| **نگه‌داشتن بیکار (Idle)** | `0` | سخت‌گیرترین گیت؛ فقط بعد از گرفتن نتیجه‌ی اول امتحان کنید |
| بررسی پاسخ HTTP | ✅ روشن | تضمین می‌کند مسیر تا لبه واقعاً کار می‌کند |
| سقف اتصال/ثانیه | `0` یا `12` | روی مخابرات/شاتل عدد ۱۰–۱۵ بگذارید |
| توقف خودکار وقتی اینترنت قطع شود | ✅ | اسکن را پارک می‌کند و بعد از برگشت خط ادامه می‌دهد |

پریست **ملایم (اینترنت ایران)** همه‌ی این‌ها را یک‌جا تنظیم می‌کند.

---

## ۴. دیدن دلیل قرمز شدن‌ها

در پنل «پیشرفت» بعد از خط دوم، تفکیک خطاها را می‌بینید:

```
fails timeout:18 reset:3 refused:1
```

| غالب بودن | یعنی | راه‌حل |
|---|---|---|
| `timeout` | دست‌دادن قطع می‌شود | `--mode tcp` یا SNI دیگری یا ورکر کمتر |
| `reset` | مسیر اتصال را می‌کشد | پریست ملایم + سقف نرخ |
| `http` | TLS سالم است ولی HTTP نه | تایم‌اوت را بالا ببرید یا `mode=tls` |
| `ws` | آپگرید وب‌سوکت همه‌جا شکست خورد | تیک WebSocket را بردارید |
| `unstable` | نگه‌داشتن بیکار همه را رد کرد | `Idle` را صفر کنید |

---

## ۵. گرفتن کانفیگ آماده (مهم‌ترین بخش)

1. در بخش «خروجی»، لینک کانفیگ خودتان را در فیلد **لینک کانفیگ** بگذارید.
   این لینک فقط به‌عنوان الگو استفاده می‌شود؛ UUID و پارامترهای شما دست‌نخورده می‌مانند.
2. **ساخت کانفیگ‌ها** را بزنید → لینک‌ها ساخته و در کلیپ‌بورد کپی می‌شوند:
   ```
   vless://uuid@104.19.26.235:443?type=ws&security=tls&sni=my.sni#EZ-104.19.26.235-99ms-38M
   ```
3. یا **دانلود کانفیگ‌ها** برای گرفتن فایل `.txt`.
4. خروجی‌های دیگر: CSV، XLSX (اکسل)، JSON، `ip:port` و «فقط آی‌پی‌ها».

> نکته‌ی امنیتی: اگر SNI همان دامنه‌ی خودتان باشد، اسکنر هشدار می‌دهد. بهتر است با یک SNI
> عمومی (مثلاً `www.cloudflare.com`) اسکن کنید و بعد آدرس‌ها را در کانفیگ خودتان بگذارید —
> همان کاری که «ساخت کانفیگ‌ها» انجام می‌دهد.

---

## ۶. اسکن روی لیست خودتان (فاز دوم)

- **تب پیست لیست**: هر خط یک آی‌پی / CIDR / رنج / `ip:port` / دامنه.
- یا در جدول نتیجه‌ها ردیف‌ها را انتخاب کنید و **اسکن فقط همین‌ها** را بزنید
  (برای تست سرعت مجدد یا بررسی دقیق‌تر با گیت‌های سخت‌گیر).

با CLI:

```bash
ezscan scan --source paste --targets my-ips.txt --speed --xlsx found.xlsx
```

---

## ۷. اسکن طولانی و ادامه‌ی آن

هر اسکن به‌طور خودکار ذخیره می‌شود (`~/.ez-scanner/sessions/`). اگر برق رفت یا سیستم
خاموش شد:

- GUI: پنل «نشست‌های ذخیره‌شده» → نشست را انتخاب کنید → **انتخاب و ادامه**.
- CLI: `ezscan resume <کد-نشست>` (کد در پایان هر اسکن چاپ می‌شود، یا `ezscan sessions`).

می‌توانید موقع ادامه تنظیمات را هم عوض کنید، مثلاً:

```bash
ezscan resume a1b2c3d4 --speed --top 30
```

## ۸. عیب‌یابی: «هیچ آی‌پی سبزی نداد»

```bash
ezscan doctor      # DNS، TCP، TLS، HTTP و مسیر تست سرعت را چک می‌کند
ezscan selftest    # چند لبه‌ی واقعی را پروب می‌کند و می‌گوید مشکل از خط است یا تنظیمات
```

- اگر `doctor` شکست خورد → مشکل خط/شبکه است (DNS، مسدودی، قطعی).
- اگر `doctor` سالم بود ولی `selftest` سبز نداد → احتمالاً TLS روی خط دستکاری می‌شود؛
  با `--mode tcp` و SNI دیگر امتحان کنید.
- اگر `selftest` سبز بود ولی اسکن شما نه → گیت‌ها سخت‌گیرند: `minScore` را `0`،
  WS و Idle را خاموش، و پریست ملایم.

---

## ۹. اجرای سرور برای استفاده از گوشی یا ماشین دیگر

```bash
ezscan gui --no-open --port 8788
```

سپس آدرس `http://<آی‌پی-لینوکس>:8788/?token=…` را در مرورگر گوشی باز کنید. (سرور
به‌صورت پیش‌فرض فقط لوپ‌بک را می‌پذیرد؛ برای دسترسی از شبکه باید bind را تغییر دهید.)

---

## ۱۰. نکات پایانی

- **سرعت اندازه‌گیری‌شده** مسیر مستقیم تا لبه است، نه سرعت نهایی تانل. برای انتخاب
  نهایی، آی‌پی‌ها را در کلاینت خودتان تست کنید.
- **آی‌پی کلادفلر دائماً تغییر می‌کند**؛ نتیجه‌ها را هر چند روز یک‌بار تازه کنید.
- **مصرف داده**: هر پروب چند کیلوبایت است؛ تست سرعت ۸ مگابایت به‌ازای هر آی‌پی
  (قابل تنظیم با «حجم دانلود»).
- **فقط روی خط و سرور خودتان استفاده کنید.**
